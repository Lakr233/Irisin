Irisin 5.0.4 installs again on a device where a package gave a file to a user only the bootstrap has, as redis-server does. Nothing on screen changes.

- **Installs no longer stop at "Unknown statoverride account".** A package's scripts may add a user to the bootstrap, as redis-tools adds `redis`, and make it the owner of a file with `dpkg-statoverride`, as redis-server does. Irisin looked that user up in iOS, which has never heard of it, and stopped every install on the device, whatever it installed. It now reads the bootstrap's own users and groups, the ones dpkg reads, and installs as `dpkg -i` does.
- **Files belong to the user the package names.** A file a package's archive gives to a user the bootstrap has is now that user's, as dpkg leaves it, rather than the number stored beside the name.
- **An unknown user says which.** An override that names a user or group the bootstrap does not have still stops an install, as it stops dpkg; the message now names the user or group and the file.
- **Removing goes past it.** Removing a package no longer reads the overrides, which `dpkg -r` never does, so a stale one no longer keeps a package from being removed.

Tested on iPhone with RootHide, iOS 26.4 and 27.0.1: a user and group added to the bootstrap, an override naming them, and a package whose files name them, installed and removed through `irisin-cli`; 5.0.3 stopped, 5.0.4 installed it with the same owners and modes the device's own dpkg gives the same package. An override naming a user nobody has stopped both Irisin and dpkg, and both removed past it. Irisin opened on both. iPad, rootless firmware and Apple TV were not tested on a device for this release.

Choose `iphoneos-arm64e` for RootHide or `iphoneos-arm64` for rootless firmware on iPhone and iPad, and `appletvos-arm64e` for RootHide on Apple TV. SHA-256 checksums are included in `SHA256SUMS`.

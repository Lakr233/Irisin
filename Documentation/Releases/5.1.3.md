Irisin 5.1.3 installs an upgrade that turns a file into a directory. The Updates page and a failed operation also stop offering a tap that does nothing.

- **An upgrade can put a directory where a file was.** When a package's new version has a directory where its old version had a file, the upgrade stopped with "Directory collides with a file" and nothing changed. On RootHide, build-essential 16.4 stopped this way on the SDK's libc++ header `__string`, which became a directory of headers. As dpkg does, the file now goes aside and the directory takes its place. If the upgrade fails after that, the file comes back. A directory still cannot take the place of another package's file unless the new package Replaces that package. (#145)
- **Open Queue on the Updates page.** Once the queue holds every update on the page, Update All becomes Open Queue and opens the queue. Before, it showed a sheet with nothing to change.
- **Try Again holds the Done button.** While Try Again prepares the run, the button that closes the page is disabled, and so is Ignore Script Errors and Retry. Before, closing the page at that moment dropped the run being prepared.

Tested with Irisin's own tests on the Mac and in the iPad simulator, and on RootHide in virtual machines: iPhone on iOS 26.4 and 27.0.1. A test package had a file in 1.0 and a directory of the same name in 2.0. Irisin 5.0.4, which has the same check as 5.1.2, stopped 2.0 with the message from the report. With the fix, on both iPhones, a version with the directory and a failing script put the file back, then 2.0 installed and the package removed cleanly. In the simulator, Update All became Open Queue once the queue held every update, and turned back when one left the queue; while Try Again prepared a large package, the Done button stayed disabled. Rootless firmware and Apple TV were not tested on a device for this release.

Choose `iphoneos-arm64e` for RootHide or `iphoneos-arm64` for rootless firmware on iPhone and iPad, and `appletvos-arm64e` for RootHide on Apple TV. SHA-256 checksums are included in `SHA256SUMS`.
